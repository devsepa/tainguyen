# Supabase shared storage implementation plan

> Execute implementation inline; perform independent final review per requesting-code-review. Follow test-driven-development and verification-before-completion.

**Goal:** shared PostgreSQL storage on Supabase Free without losing browser data.
**Architecture:** independent REST adapter, transactional SQL updates with optimistic revision checks, UI activation after project/access information arrives.
**Tech stack:** existing HTML/JavaScript, fetch, PostgreSQL, Supabase Data API.
**Spec:** ../specs/2026-11-25-supabase-design.md

## Constraints

- No paid services. No server secrets or account data in GitHub.
- Do not enable anonymous access before the user confirms it.
- Preserve current local data and working website while setup is pending.

## Review focus

Pagination above 1,000 rows; stale writes/deletes; retries after ambiguous network failures; storage access denial; local records remain untouched during preparation.
