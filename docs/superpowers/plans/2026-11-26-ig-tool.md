# Local Instagram Tool Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run one visible registration session using warehouse mail, user inputs,
proxy diagnostics, automatic or manual OTP, and conservative result saving.

**Architecture:** A loopback server serves the existing warehouse and a protected
job API. Separate input/proxy, mailbox, browser adapter, runner, and UI modules.
Existing warehouse operations supply mail and persist successful results.

**Tech Stack:** Node.js 22+, Playwright, proxy-chain, built-in Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-26-ig-tool-design.md`

## Global Constraints

- One visible browser session at a time; no real registration during verification.
- Never embed credentials supplied in chat.
- Proxy failure must never fall back to a direct connection.
- Secrets remain in memory; no database schema changes or privileged keys.
- Success requires a logged-in identity matching the requested username.

## Review Focus

- Authenticated SOCKS5 must work through a relay, not unsupported browser auth.
- Old, unrelated, or wrong-recipient OTP must not be submitted.
- Cancellation during network/browser work must release all resources.
- Reopening the page must not lose access to an unsaved completed result.
- Failed or conflicting warehouse writes must leave the result available to retry.
